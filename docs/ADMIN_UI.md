# 管理站点产品与交互规格

> 本站点是部署机上的运维工作台，不是营销页或公开资讯站点。目标是让使用者在一分钟内判断系统是否健康，并在不查库、不翻原始日志的情况下完成授权、公众号管理和采集排查。

> 实施状态（2026-07-30）：登录、总览、本机微信扫码、公众号添加/归档/恢复、手工入队、采集记录、文章和诊断页面已实现。SSE、全局状态条、设置页和飞书二维码投递仍属于后续目标，不应视作当前入口。

## 1. 技术与访问方式

- FastAPI + Jinja2 服务端渲染。
- 少量原生 JavaScript；运行状态使用 SSE，断线时有限轮询降级。
- 第一阶段不增加 Node 构建链和 SPA 框架。
- 监听 `127.0.0.1:4101`，入口 `http://127.0.0.1:4101/admin`。
- 管理员密码由 CLI 初始化，密码哈希和 session signing key 存 Credential Vault。
- 登录后会话闲置 8 小时失效；所有写操作使用 CSRF token。

## 2. 导航与布局

```text
┌──────────────┬──────────────────────────────────────────────┐
│ 系统名称      │ 全局状态条：正常 / 采集中 / 冷却 / 需授权       │
│              ├──────────────────────────────────────────────┤
│ 总览          │                                              │
│ 微信授权      │                 主内容区                      │
│ 公众号        │                                              │
│ 采集记录      │                                              │
│ 文章          │                                              │
│ 诊断          │                                              │
│ 设置          │                                              │
└──────────────┴──────────────────────────────────────────────┘
```

- 桌面端固定侧栏；窄屏折叠为菜单。
- 页面区块使用分隔线和留白，不把整页切成浮动卡片。
- 表格紧凑、可扫描；状态使用图标 + 文本 + 颜色，不能只靠颜色。
- 图标按钮使用 Lucide 图标并提供 tooltip。
- 所有固定状态区域预留尺寸，加载和文字变化不能引发布局跳动。

## 3. 全局状态模型

状态条只显示一个最高优先级状态：

| 优先级 | 状态 | 判定 | 主动作 |
|---:|---|---|---|
| 1 | 需重新授权 | credential state 为 expired/missing | 打开微信授权 |
| 2 | 频控冷却中 | `cooldown_until > now` | 查看恢复时间 |
| 3 | 最近批次失败 | 最新 scheduled run 为失败终态 | 查看批次 |
| 4 | 采集中 | 存在 running run | 查看进度 |
| 5 | 数据过旧 | 最近成功批次超过阈值 | 查看调度状态 |
| 6 | 正常 | 以上均否 | 无 |

页面刷新和状态轮询只读数据库，禁止因此访问微信。

## 4. 页面规格

### 4.1 登录页 `/admin/login`

- 字段：管理员密码。
- 操作：登录。
- 错误：统一显示“凭据无效”，不透露用户是否存在。
- 连续失败应本地限速；无默认密码。
- 已登录访问该页直接跳转总览。

### 4.2 总览 `/admin`

首屏从上到下：

1. 全局状态条及可执行动作。
2. 最近定时批次：状态、开始/结束、覆盖 `成功/计划`、请求数、新增数、耗时。
3. 授权摘要：脱敏账号、状态、最近验证时间、凭据版本。
4. 下一次计划：预计 `23:50-23:52`、调度器/Worker 心跳。
5. 需要关注：缺失公众号、连续失败、接近预算、异常空列表。
6. 最近发现文章：最多 10 条。

主操作：

- “重新授权”：跳转授权页。
- “立即采集”：打开确认对话框，不直接提交。

确认对话框显示目标公众号数、当前预算余量、预计最短耗时、冷却状态。确认后 `POST /collection-runs`，成功立即跳转 queued 批次详情。

空状态：没有任何批次时显示“尚未采集”，提供添加公众号或授权动作，不显示虚假的 0% 失败。

### 4.3 微信授权 `/admin/wechat-auth`

顶部使用分段控件：`本机扫码 | 飞书扫码`。

#### 本机扫码

| 状态 | 界面 |
|---|---|
| 无活动会话 | 当前授权摘要 + “生成二维码” |
| `creating` | 固定 280x280 二维码区域内 loading |
| `waiting_scan` | 二维码、倒计时、取消 |
| `scanned` | 二维码弱化，提示在手机确认 |
| `confirming/validating` | 显示验证进度，禁用重复生成 |
| `succeeded` | 新授权摘要、完成时间、返回总览 |
| `expired` | 明确过期，允许重新生成 |
| `failed` | 稳定原因和重新生成；旧授权状态单独展示 |

刷新页面根据 login session 恢复状态，不创建新会话。二维码容器使用 `aspect-ratio: 1`。页面和 DOM 不出现微信 UUID。

#### 飞书扫码

- 显示飞书适配器是否已配置。
- 目标会话来自后端允许列表，不允许自由输入任意 chat ID。
- 点击“发送二维码”后显示发送结果、有效期和扫码状态。
- 飞书端只收到二维码和状态通知，不发送管理页链接或凭据。
- 若存在本机活动二维码，复用同一登录会话并发送同一二维码。

互斥状态：正在采集时“生成/发送二维码”禁用并说明需等待；登录进行中“立即采集”保持 queued 或不允许重复提交。

### 4.4 公众号 `/admin/accounts`

默认页签为 `正在订阅`，另有 `已暂停` 和 `已归档`。正在订阅表格支持多选，选中后顶部批量工具栏显示“采集所选（N）”。表格字段：

```text
选择 | 顺序 | 名称 | 队列状态 | 启用 | 最近成功 | 最近文章 | 水位线 | 连续失败 | 操作
```

交互：

- 启停使用 switch；关闭前提示不会删除历史文章。
- 顺序使用拖拽把手或上下箭头；保存后成为基础顺序。
- 单个采集使用播放图标，提交前显示预算和冷却。
- 行内队列状态为 `空闲/已排队/采集中`；采集中按钮禁用，点击不会重复提交。
- 选择多个公众号后点击“采集所选”，只提交一次命令，后端拆成公众号队列并串行执行。
- 提交结果对话框逐项展示 `已入队/已提升已有队列/正在采集已忽略/不可采集`，忽略不能静默发生。
- 人工 job 优先于尚未开始的定时 job，但不会中断当前正在执行的公众号。
- 行操作菜单提供“删除订阅”。确认文案必须说明：它会从采集计划移除公众号，但保留历史文章和批次，可在“已归档”中恢复。
- 已归档页只提供“恢复订阅”；恢复后默认处于暂停状态，由用户再次启用。
- 暂停或归档从下一批次生效；若当前批次已经 running，确认框提示该公众号本次仍可能被采集一次。
- 内部 fakeid/source id 默认不展示。

“添加公众号”侧边面板：

1. 输入关键词。
2. 必须点击搜索，不做输入即搜和自动重试。
3. 提交后展示 queued/waiting 状态及预计最早请求时间。
4. 候选列表显示头像和名称。
5. 用户选中后确认添加；新订阅默认启用并进入下一次定时计划，但添加动作本身不触发采集。
6. 重复 source_account_id 返回已存在公众号并定位该行；若已归档，提示恢复原订阅。

前端不提供“同时删除全部历史文章”。真正物理删除只属于维护 CLI，且仅允许从未产生历史引用的公众号。

#### 定点采集耗时提示

- 只选 1 个公众号：最多 3 页，通常约 1-11 分钟；每页是 5 个发布记录，不是固定 5 篇文章。
- 选择 N 个公众号：最多 `3 × N` 次请求，全部串行。
- 页面显示队列位置、当前处理公众号和预计最早开始时间，不承诺精确完成时刻。
- 全局冷却或授权失效时批量按钮禁用，并直接显示恢复时间或授权入口。

### 4.5 采集记录 `/admin/runs`

筛选：日期范围、状态、触发方式。默认按开始时间倒序。

字段：开始时间、触发方式、状态、覆盖率、请求数、新增/更新、耗时、发起人。

- running 行显示稳定进度，不使用不确定的无限动画作为唯一反馈。
- `rate_limited/session_expired/protocol_changed` 显示明确图标。
- 游标分页；切换筛选后清空旧游标。

### 4.6 批次详情 `/admin/runs/{id}`

页面使用三个并列纵向区块，不嵌套卡片：

1. **批次摘要**：状态、触发方式、业务日期、开始/结束、覆盖、请求、文章增量、停止原因。
2. **公众号执行表**：计划顺序、状态、页数、返回/新增/更新、耗时、原因。
3. **事件时间线**：该 run_id 的重要事件和 request_id，可展开脱敏细节。

运行期间订阅 SSE；断线后每 10 秒轮询，终态后停止。`not_started` 显示“未执行”，绝不能显示成“0 篇成功”。

终态动作：

| 终态 | 动作 |
|---|---|
| `completed/partial` | 查看新增文章 |
| `rate_limited` | 查看冷却截止，不提供立即重试 |
| `session_expired` | 前往微信授权 |
| `protocol_changed` | 复制诊断摘要 |
| `failed` | 查看事件、复制诊断摘要 |

### 4.7 文章 `/admin/articles`

筛选：公众号、发布时间范围、首次发现范围、标题关键词。默认 `published_at DESC`。

字段：标题、公众号、发布时间、首次发现、最近观察、源链接。

- 标题点击进入本地详情；外链图标在新标签打开微信原文。
- 封面加载失败使用固定占位，不改变表格行高。
- 空结果区分“数据库没有文章”和“当前筛选无结果”。

详情 `/admin/articles/{id}` 显示：当前元数据、revision 时间线、出现过的批次及页码位置。该页面只读。

#### 大数据量展示规则

- 页面首次只加载 50 条，滚动或点击“下一页”使用不透明 cursor；不得一次读取全部文章。
- 筛选、排序和关键词搜索全部在服务端执行，浏览器不持有全量文章数组。
- 列表响应不包含 revision、观察历史、源 payload 和总量精确 COUNT。
- 输入关键词后 300 ms debounce，但必须达到 2 个字符；请求可取消，旧响应不能覆盖新结果。
- 切换筛选条件时清空 cursor，并保持当前条件在 URL query 中，便于刷新恢复。
- 封面设置固定尺寸、`loading="lazy"`、`decoding="async"`；首屏外图片不提前加载。
- 表格 DOM 同时不超过约 100 行。若采用连续加载，追加前应回收远离视口的行；第一阶段优先普通分页。
- 详情页独立请求 revision 和观察历史，观察历史最多 100 条并继续游标分页。
- 文章总数使用异步汇总值并标注统计时间，不为列表实时扫描全表。

未来公开站点默认每页 20 条，使用 HTTP cache/ETag。若微信封面存在防盗链或延迟问题，再增加受控图片代理/CDN；第一阶段先使用懒加载和失败占位，不把远程图片二进制存入 SQLite。

### 4.8 诊断 `/admin/diagnostics`

数据源为 `collection_events` 和脱敏 `wechat_requests`，不直接读取/下载服务器日志。

筛选：时间、级别、事件类型、run_id、account_id、request_id。

“复制诊断摘要”仅包含：应用版本、schema 版本、时间、稳定状态/原因码、批次统计、request_id。禁止包含 Cookie、token、fakeid、搜索词、原始响应和堆栈。

### 4.9 设置 `/admin/settings`

第一阶段只读显示：

- 调度时间、时区和启动抖动。
- 请求间隔、抖动、页上限、每日预算和当前余量。
- 当前冷却截止。
- 数据库路径脱敏值、migration 版本、最近备份和恢复验证时间。
- Worker、Read API、飞书适配器状态。
- Admin/Read API 监听地址。

频控、端口和秘密不允许在线修改。页面提供“复制生效配置摘要”，不展示密钥值。

## 5. 通用页面状态

每个数据区域都必须实现：

| 状态 | 要求 |
|---|---|
| loading | 保持稳定尺寸，避免跳动 |
| empty | 说明是无数据还是无筛选结果 |
| stale | 显示数据时间和刷新本地状态操作 |
| partial | 显示缺失范围，不伪装完整 |
| failed | 稳定原因码、可执行下一步 |
| offline | Admin API 不可用提示，不触发微信重试 |
| unauthorized | 跳登录，保留安全的 return path |

错误文案不包含原始异常。按钮进行中要禁用重复提交；幂等键仍是后端最终保证。

## 7. 前端安全

- Admin 即使监听 loopback 也必须登录，不能使用默认密码。
- session Cookie：`HttpOnly`、`SameSite=Strict`；启用 HTTPS 时加 `Secure`。
- POST/PATCH/DELETE 必须带 CSRF token。
- 外部标题、摘要和 URL 做 HTML 转义；仅允许 `https` 外链。
- 飞书命令仅接受用户 ID 白名单；群聊中非白名单成员不能触发授权。
- 二维码接口只对当前管理员会话开放，并设置 `Cache-Control: no-store`。
- 浏览器端日志不打印 API 完整响应。

## 8. 响应式与可访问性

- 验证桌面 `1440x900`、小屏笔记本 `1024x768`、手机 `390x844`。
- 所有按钮、输入和状态可用键盘访问，并有清晰 focus ring。
- 图标按钮有 `aria-label` 和 tooltip。
- 表格在手机上转换为字段清晰的行列表，不做横向无限滚动作为唯一方案。
- 文本不使用 viewport 宽度缩放；长标题最多两行，完整值在详情页查看。
- 状态颜色满足对比度，并始终带文字。

## 9. Playwright 验收

1. 未登录访问任意 `/admin/*` 会跳转登录页。
2. 总览在正常、冷却、需授权、running、无批次五种 fixture 下无重叠。
3. 本机二维码从 creating 到 succeeded 的全部状态可恢复刷新。
4. 重复点击生成二维码/立即采集只产生一个后端对象。
5. 批次详情能区分 completed、failed、not_started。
6. 公众号搜索不会因输入或页面刷新自动发请求。
7. 文章列表游标分页和筛选保持稳定。
8. 三个目标 viewport 截图无横向溢出、遮挡和按钮文字截断。
9. HTML/浏览器控制台中不存在 Cookie、token、fakeid 或微信 UUID。
10. 使用百万文章 API fixture 时，页面只请求当前 cursor，不出现全量加载或超过 100 行 DOM。
11. 快速连续改变关键词/筛选时，最终页面只展示最后一次请求结果。
